# std/x509

X.509 certificates for a TLS client: strict DER parsing, PEM, the system's trusted roots,
chain building and verification, and host name matching (RFC 5280, RFC 6125). Signatures are
checked by `std/pubkey` (RSA PKCS#1 v1.5 and PSS, ECDSA P-256/P-384, Ed25519).

```caju
import "std/x509"
import "std/os"

pem, _ := os.read_file("chain.pem")
certs, err := x509.parse_pem(pem)
if err != nil { panic(err.Error()) }
chain, err := x509.verify(certs[0], &x509.VerifyOptions{dns_name: "example.com", intermediates: certs[1:]})
if err != nil { print(err.Error()) }    # x509: certificate is valid for a.com, b.com, not example.com
```

## Parsing

| function | |
|---|---|
| `parse(der)` | one certificate in DER → `(*Certificate, error)` |
| `parse_pem(text)` | every `-----BEGIN CERTIFICATE-----` block (other blocks are ignored); one bad certificate fails the whole call |
| `load_roots(file)` | a PEM bundle, skipping the certificates that do not parse |
| `system_roots()` | the trusted roots, loaded once: `$SSL_CERT_FILE`, or the first of `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/ca-bundle.pem`, `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, `/etc/ssl/cert.pem` |

The parser is strict DER: single-byte tags, definite and minimal lengths, no trailing data
anywhere, the inner and outer signature algorithms must agree, extensions only in v3 and never
twice. Hostile input gives an error (`x509: malformed certificate: ...`), never a crash.

`Certificate` fields:

| field | |
|---|---|
| `raw`, `tbs` | the whole certificate and the signed `tbsCertificate` (DER) |
| `version` | 1, 2 or 3 |
| `serial` | the serial number's INTEGER bytes |
| `sig_alg_oid`, `sig_alg_params` | the signature algorithm (dotted OID) and its DER parameters |
| `signature` | the signature bytes |
| `issuer_raw`, `subject_raw` | DER of the names (chains are matched on them) |
| `issuer`, `subject` | readable names, most specific first: `CN=github.com, O=GitHub, Inc., C=US` |
| `common_name` | the subject's CN (informative only: never used for host names) |
| `not_before`, `not_after` | unix seconds (UTCTime and GeneralizedTime); `format_time(t)` gives `2026-01-31 12:00:00 UTC` |
| `spki`, `key_alg_oid`, `key_params` | the DER SubjectPublicKeyInfo, its algorithm and parameters (the curve OID of EC keys) |
| `dns_names`, `ip_addresses`, `email_addresses`, `uris` | subjectAltName entries (IPs as text: `127.0.0.1`, `2001:db8::1`) |
| `has_basic_constraints`, `is_ca`, `path_len` | basicConstraints (`path_len` -1 when absent) |
| `has_key_usage`, `key_usage` | keyUsage bits: `KU_DIGITAL_SIGNATURE`, `KU_KEY_ENCIPHERMENT`, `KU_CERT_SIGN`, `KU_CRL_SIGN`... |
| `ext_key_usage` | extKeyUsage OIDs (`EKU_SERVER_AUTH`, `EKU_CLIENT_AUTH`, `EKU_ANY`) |
| `subject_key_id`, `authority_key_id` | key identifiers |
| `name_constraints_present` | the certificate has nameConstraints |
| `has_unknown_critical` | a critical extension this module does not understand |

Understood extensions: basicConstraints, keyUsage, extKeyUsage, subjectAltName, the key
identifiers and nameConstraints; certificatePolicies, CRL distribution points, authority
information access and SCTs are accepted and ignored. Any other critical extension sets
`has_unknown_critical`.

## Verifying

```caju
export struct VerifyOptions {
  dns_name: str                  # host name or IP address ("" skips the check)
  roots: []*Certificate          # nil: system_roots()
  intermediates: []*Certificate  # untrusted certificates that may complete the chain
  now: int                       # unix seconds; 0: now
}
```

`verify(leaf, opts)` returns the chain it used (leaf first, trusted root last). It checks:

- the leaf: validity dates, no unknown critical extension, extKeyUsage (if present) includes
  serverAuth or anyExtendedKeyUsage, and the host name;
- the chain, built from the leaf through `intermediates` to one of `roots` (issuer matched by
  `subject_raw == issuer_raw`, candidates with the matching key identifier first; alternatives
  are tried, loops avoided, at most 8 certificates): every signature, the dates of every
  certificate, every issuer is a CA (basicConstraints cA; a v1 root without extensions is
  accepted), its keyUsage (if present) has keyCertSign, its path length constraint holds, an
  intermediate has no unknown critical extension.

A leaf that is itself one of the roots is accepted as a chain of one.

`match_hostname(cert, host)` alone: a DNS name matches a dNSName SAN ignoring case and a final
dot; `*.example.com` matches exactly one left-most label (`a.example.com`, not `example.com` nor
`a.b.example.com`); `*`, `*.com` and partial wildcards (`f*.example.com`) never match. An IP
address (`10.0.0.1`, `::1`, `[::1]`) is matched against the IP SANs only. The common name is
never used.

`signature_algorithm(cert, issuer_spki)` gives the `std/pubkey` name of a certificate's
signature (`rsa-pkcs1-sha256`, `rsa-pss-sha384`, `ecdsa-p256-sha256` (the curve comes from the
issuer's key), `ed25519`...); `check_signature_from(cert, parent)` checks that one signature.

Errors say what failed:

```
x509: certificate is valid for example.test, www.example.test, not example.org
x509: certificate expired on 2026-01-27 23:59:59 UTC: CN=example.test
x509: certificate signed by unknown authority (issuer "CN=Some CA, O=Some Org")
x509: "CN=Not A CA" is not a CA (basicConstraints), it cannot sign certificates
x509: path length constraint of "CN=Intermediate" exceeded (pathlen 0)
x509: bad signature on "CN=example.test" by "CN=Intermediate": ...
```

## Not supported

- Name constraints: a chain through a CA that has them is refused with a clear error.
- Revocation (CRL, OCSP), certificate policies, policy constraints (a critical
  policyConstraints or inhibitAnyPolicy counts as an unknown critical extension).
- Unknown critical extensions on trust anchors are not checked (the root is trusted as configured).
- extKeyUsage is checked on the leaf only, not nested through the intermediates.
